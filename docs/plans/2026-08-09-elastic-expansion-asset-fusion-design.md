# 弹性扩张：续写侧创作资产强关联设计

日期：2026-08-09
状态：已获用户批准（方向 + 四节设计 + 弹性配额修订）

## 背景与问题

用户核心抱怨：小说人物角色少、场景单一、世界构建简单、故事冲突不足、故事线推进不快。

现状摸底（2026-08-09 代码级核查）结论：**问题不在"资产没注入"**。v0.31.0（2026-08-04 资产融合重构）后，续写 prompt（`WriteTimeBundle.to_prompt()`，`write_time_bundle.rs:582`）已注入 13+ 段：世界观红线、大纲、角色核心+当前状态、体裁反模式、风格片段、叙事阶段、伏笔、活跃冲突、角色目标/弧光/秘密、追读力债务、风格 DNA、方法论约束（含 custom 技能书方法论）、体裁画像策略。真正的问题是：

1. **模型没有被强制使用这些资产**：prompt 给了角色卡但没说"该让沉寂角色登场了"；给了冲突引擎 21 种模式（`builtin_*()` Rust 常量库）但主流程从不挑选使用
2. **资产选择静态化**：LLM 版 `StrategySelector::select_strategy`（`strategy/selector.rs:34`）只在手动命令（`commands/strategy.rs:41`）用，创作主流程不调用
3. **无场景/角色使用的反馈数据**：模型不知道哪些场景用滥了、哪些角色沉寂了

## 目标

让续写流程在**不显著增加 LLM 调用成本**（用户选定"平衡"档：每章 +0~1 次小调用）的前提下，产出场景更丰富、角色更多更活、冲突更密集、推进更快的内容。

非目标：质量反馈环（critic 打分回炉，留作远期可选开关）；创世 agency 链路贯通（第二期，见文末提纲）。

## 设计总览

三个互相咬合的机制 + 一套降级与测试：

```
轮换账本（数据）──→ 扩张债务（判定）──→ 弹性配额（强制）
        │                                      ↑
        └──── 动态资产选择（菜单+精选）─────────┘
```

## 1. 轮换账本（数据层）

`WriteTimeBundle` 新增注入段（⑧e），提供两类聚合数据：

- **场景使用账**：近 10 章各场景的使用次数（从章节场景记录推导）
- **角色沉寂账**：主要角色距上次登场的章数（从 ingest 已有的角色状态/出场记录推导，大概率只需查询聚合；若现有表推导不出，补轻量章节-场景/角色出场记录）

配指令文案：优先选用低使用次数场景；沉寂 ≥3 章的主要角色列入本章回归候选。

纯数据注入 + 指令，无新 LLM 调用。数据缺失时整段省略（沿用 bundle 现有容错模式），旧书无需迁移。

## 2. 扩张债务与弹性配额（判定+强制层）

跟踪四项**扩张债务**（由账本数据直接算出）：

| 债务 | 定义 | 阈值（默认，可调） |
|---|---|---|
| 冲突停滞度 | 连续章数无冲突线升级 | 2 章 |
| 场景固化度 | 连续章数无新场景 | 3 章 |
| 角色固化度 | 连续章数无新角色/沉寂角色回归 | 3 章 |
| 伏笔停滞度 | 连续章数无新埋/回收伏笔 | 3 章 |

运行规则：

- **低于阈值**：对应配额项不出现，beat_planner 自由发挥，零套路化干扰
- **达到阈值**：对应配额项进入 beat 计划必填任务；债务越深措辞越强（"建议开辟新场景"→"本章必须离开当前场景"）
- 配额块动态 0-4 项：平稳期零干扰，停滞期逐级加压

配额项内容：

- `new_scene`：新场景名称 + 剧情关联
- `character_move`：登场角色及行动目的；触发时须含 ≥1 沉寂角色回归或新配角
- `conflict_escalation`：从活跃冲突列表选 1 条升级，注明方式（加压/反转/代价显现）
- `foreshadow_move`：埋 1 条新伏笔或回收 1 条到期伏笔

beat_planner 输出 schema 扩展该块；writer 模板（`orchestrator_timesliced_writer.md`）渲染为硬性任务清单。不新增 LLM 调用（配额在现有 beat 规划调用内产出）。

## 3. 动态资产选择（菜单+精选）

两段式，控制 token 成本：

- **Rust 侧粗筛**（零 LLM）：从 31 张桥段卡 + 21 种剧情引擎 + 13 种高压关系（`builtin_*()` 常量库）中，按叙事阶段 + 当前冲突状态 + 轮换历史（近 K 章用过的排除，K 默认 5）选出 5 个候选，以一行摘要进 beat_planner 菜单
- **beat_planner 精选**：从候选挑 1-2 个并写明用法，随 beat 计划传 writer

选中资产 ID 记入章节元数据形成轮换历史。不搬整体 `StrategySelector`，主流程调用次数不变。

## 4. 降级与测试

降级：

- beat_planner 超时/失败 → 现有降级路径，Rust 侧按当前债务状态注入默认配额文案
- 账本/资产菜单数据缺失 → 对应段省略，行为回退现状
- 旧书无历史数据 → 债务初始为 0，自然进入"低干扰"状态

测试（复用 src-tauri 现有基建）：

- 单元：债务计算（各阈值边界）、账本聚合、资产粗筛启发式（轮换排除、阶段匹配）
- 渲染：配额块在 beat 计划/writer prompt 中的渲染断言；债务触发与否的文案差异
- 回归：src-tauri 全量测试不回归
